### [MEDIUM] CompleteReceivingSession skips site access when site_id is null `F-2026-0004`
**Rule:** `AUD-SEC-001` — Security
**Severity:** Medium
**Confidence:** Confirmed
**Status:** Open
**Summary**
CompleteReceivingSession only calls SiteAccess::assertCanAccessSite when session.site_id is non-null. CancelReceivingSession denies null-site completions without SitesAccessAll. A user with NavReceive can complete a null-site transfer/ASN session that cancel would block.
**Why it matters**
Site-scoped custody controls are inconsistent on a durable receiving state transition; wrong-site or unscoped completes weaken DSCSA operational controls.
**Evidence**
- `file` — app/Actions/Receiving/CompleteReceivingSession.php:62-65
 - Site assert gated on site_id !== null
- `file` — app/Actions/Receiving/CancelReceivingSession.php:60-68
 - Null site_id denied without SitesAccessAll (contrast)
**Affected resources**
- `app/Actions/Receiving/CompleteReceivingSession.php`
- `app/Actions/Receiving/CancelReceivingSession.php`
**Recommendation**
Align CompleteReceivingSession with CancelReceivingSession: require SitesAccessAll (or equivalent) when site_id is null, or refuse completion until a site is assigned.
**Verification notes**
Source comparison of both actions; ReceivingSessionPolicy exists but these Action entry points enforce JobRoleAccess + SiteAccess directly.

### [MEDIUM] Long-running jobs declare timeouts far above database queue retry_after default `F-2026-0009`
**Rule:** `AUD-QUE-001` — Laravel conventions
**Severity:** Medium
**Confidence:** High
**Status:** Open
**Summary**
config/queue.php defaults QUEUE_CONNECTION to database with retry_after 90 seconds, while ProcessEpcisDocumentJob and other jobs set timeout of 600-3600. If an environment falls back to the database driver without raising DB_QUEUE_RETRY_AFTER, in-flight jobs can be released and duplicated.
**Why it matters**
Duplicate EPCIS processing or FDA imports can corrupt custody/event state or create conflicting side effects.
**Evidence**

 - default => env QUEUE_CONNECTION database
- `config` — config/queue.php:38-43
 - database.retry_after defaults to 90
- `file` — app/Jobs/ProcessEpcisDocumentJob.php:22-24
 - timeout = 600; tries = 3
**Affected resources**
- `config/queue.php`
- `app/Jobs/ProcessEpcisDocumentJob.php`
**Recommendation**
Keep production on redis/Horizon with retry_after greater than max job timeout; raise database retry_after if database driver is ever used; assert this in deploy checks.
**Verification notes**
Config and job properties inspected. .env.example uses redis (mitigation), but code defaults remain unsafe.
