[MEDIUM] CompleteReceivingSession skips site access when site_id is null (Security, confidence: Confirmed)
 Rule: AUD-SEC-001
 Symbol: CompleteReceivingSession::handle
 Evidence: app/Actions/Receiving/CompleteReceivingSession.php:62
 Evidence: app/Actions/Receiving/CancelReceivingSession.php:60
 CompleteReceivingSession only calls SiteAccess::assertCanAccessSite when session.site_id is non-null. CancelReceivingSession denies null-site completions without SitesAccessAll. A user with NavReceive can complete a null-site transfer/ASN session that cancel would block.
 Recommendation: Align CompleteReceivingSession with CancelReceivingSession: require SitesAccessAll (or equivalent) when site_id is null, or refuse completion until a site is assigned.

[MEDIUM] Account security flags are mass-assignable on User/Admin/PortalUser (Security, confidence: High)
 Rule: AUD-SEC-002
 Evidence: app/Models/User.php:33
 Evidence: app/Models/Admin.php:36
 Evidence: app/Models/PortalUser.php:17
 User and Admin fillable include is_active and must_change_password; PortalUser includes is_active. session_version is correctly not fillable. Filament forms intentionally write these fields, but any other fill()/create() from request-shaped arrays can flip account usability.
 Recommendation: Remove security flags from fillable and set them only via dedicated methods (disable/enable/forcePasswordChange) or guarded admin form dehydrators.
[MEDIUM] Long-running jobs declare timeouts far above database queue retry_after default (Laravel conventions, confidence: High)
 Rule: AUD-QUE-001
 Evidence: config/queue.php:16
 Evidence: config/queue.php:38
 Evidence: app/Jobs/ProcessEpcisDocumentJob.php:22
 config/queue.php defaults QUEUE_CONNECTION to database with retry_after 90 seconds, while ProcessEpcisDocumentJob and other jobs set timeout of 600-3600. If an environment falls back to the database driver without raising DB_QUEUE_RETRY_AFTER, in-flight jobs can be released and duplicated.
 Recommendation: Keep production on redis/Horizon with retry_after greater than max job timeout; raise database retry_after if database driver is ever used; assert this in deploy checks.
