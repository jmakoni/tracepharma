# BH5 Bug Hunt Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remediate BH5 Wave 1 (Admin registry/hub/dashboard authz + App VRS site visibility) then Wave 2 (pair rollback, SFTP fail-closed, EPCIS JobRoleAccess, SLA recovery, onboarding slug release).

**Architecture:** Fail-closed Filament `canViewAny` / `canEdit` / `canAccess` gates using existing `Permissions::*` on the admin guard; widget catalog aligned to the same permissions; App lean metrics hide unscoped VRS for site-restricted users. Wave 2 hardens provisioning rollback and outbound/EPCIS operator paths without new permission constants.

**Tech Stack:** Laravel 13, Filament 5, Spatie Permission (admin guard), Pest/PHPUnit, central + tenant DB (Admin tests: `DatabaseTransactions` only).

**Spec:** `docs/superpowers/specs/2026-08-16-bh5-bug-hunt-design.md`

## Global Constraints

- No new Spatie permission names — only `admins.manage`, `catalog.manage`, `tenants.manage`.
- Do not use `RefreshDatabase` / `migrate:fresh` on central Admin tests — use `DatabaseTransactions`.
- Minimal diffs; no drive-by refactors; no plan file edits under `~/.cursor/plans` unless asked.
- Support keeps **read-only** FDA registry list/view and registry lean widgets.
- Per bug: failing test → fix → green; root cause before patch (`systematic-debugging`).
